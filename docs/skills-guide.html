Skills Guide

Which Skill to use at each stage, and when — so anyone can follow along and run a full QA pipeline

Blue = skill command · optional = optional step · for the full pipeline overview see pipeline.html

Two-Layer Architecture

Layer 1 · Orchestration

Guides you / picks for you

/flow-qa-router — when you don't know which one to use, describe your scenario and it picks the skill.

/flow-feature-testing-workflow and /flow-version-testing-workflow walk you step by step through an entire stage.

Layer 2 · Execution

Individual skills that do the work

test-matrix / state-machine / write-bdd / bdd-review / version-test-plan / tc-merge / jira-sync … each does one thing and can be called on its own.

Feature Stage single feature: design → test

Goal: turn one feature ticket into executable test assets. Don't skip the order — drawing the state machine before the matrix is verified tends to drift the scope; writing cases before the state machine is drawn tends to miss edge cases.
Step 1

/stage-test-matrix

Generate a "condition × behavior" Test Matrix from the ticket or plan.md, applying the ten coverage techniques for exhaustive coverage (equivalence classes / boundary values / decision tables …).

argument TICKET-xxx

Step 2 optional

/stage-state-machine

Draw a Mermaid State Machine covering legal + illegal transitions, filling in the state flows the matrix easily misses.

prerequisite test_matrix.md

Step 3

/stage-write-bdd

Write Gherkin .feature from the matrix (New: whole file / Modified: diff); each scenario maps to one ticket.

prerequisite test_matrix.md

Step 4 optional

/stage-ui-prototype

Produce an interactive HTML prototype so stakeholders can confirm scope against the screens.

prerequisite test_matrix.md

Step 5 optional

/stage-bdd-review

Dispatch an independent subagent to review the BDD and score it /100 (report only, no file changes).

argument TICKET-xxx or cases path

Step 6 optional

/stage-jira-sync

Sync the test artifacts to Jira, creating a TEST Sub-task under the feature ticket for archiving.

argument TICKET-xxx

Want to be walked through step by step without memorizing the order → just run /flow-feature-testing-workflow TICKET-xxx.

Version Stage which features the version includes → aggregate → release gate

Step 1 · Entry point

/stage-version-test-plan

Pull this version's feature list, assign lead testers, define the scope and the integration / regression range, and create the versions/{version}/ container + plan.md.

argument vX.X

↓
Step 2 · Per feature

matrix → state machine → BDD → review

Only tickets with changes in this version re-run the corresponding stages, scoped to the change (/stage-test-matrix → /stage-state-machineoptional → /stage-write-bdd → /stage-bdd-reviewoptional); unchanged tickets reuse the existing artifacts from the Feature stage and need no re-run.

argument vX.X TICKET-xxx

Step 3 · Wrap-up

integration + regression matrix / BDD

Aggregate across features and add integration and regression scenarios (regression goes in testcases/regression/).

Step 4 · Release gate

/tool-qa-release-gate

Aggregate the pass rate, open bugs, and risk, compute readiness, produce a signable sign-off, and make the go / no-go call.

argument vX.X · depends on /tool-scan-qa-risk

Step 5 · Merge back

/stage-tc-merge

After sign-off, merge the approved .feature files back into the testcases/ main library (the only skill allowed to write to the main library).

argument vX.X · prerequisite: signed off, no further changes

Want to be walked through step by step → /flow-version-testing-workflow v4.16.

Persistent Tools not stage-bound · available anytime

/tool-root-cause-analysis

CS-reported, ticket already created: reproduce → confirm whether it's a bug → privately judge frontend vs backend. By default, no new ticket is created and the root cause is not written to the ticket.

argument symptom or an existing TICKET-xxx

/tool-open-qa-bug

Found a bug and need to file a report: gather information, deduplicate, and create a Bug subtask under the feature ticket.

argument: none (natural language)

/tool-scan-qa-risk

During sprint planning, rate each ticket HIGH/MED/LOW risk and output a risk matrix + test priority order.

argument sprint name or TICKET-xxx …

/tool-qa-release-gate

Go/no-go release gate for version wrap-up / before shipping.

argument vX.X

Automation & Engineering E2E implementation and CI

/auto-playwright-agentic-automation-workflow

Add the Playwright implementation for existing @auto scenarios: planner walks through live to extract real locators → generator writes code from the evidence → verify → healer fixes residual failures.

argument feature path / @tag / scenario / empty

/auto-responsive-layout-check

Scan responsive layout / overflow across viewports (standalone spec, not part of BDD).

argument list of page paths / empty

/auto-console-error-collector

Build a console error-interception fixture that adds a layer of JS error protection to every E2E.

argument: none

/auto-test-impact-analyzer

Compute the affected test subset from the git diff so a PR runs only the relevant subset and shortens CI.

argument base branch / empty

/auto-tc-version-diff

Compare BDD differences between two versions (Added/Modified/Removed) + produce a supplementary test list.

argument <old version> <new version>

/auto-code-review · /auto-create-pull-request

Run a framework code review on the current branch diff (100-point scale); generate a PR description and submit it.

argument: none
