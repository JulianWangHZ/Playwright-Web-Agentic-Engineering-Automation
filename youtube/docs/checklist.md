**Step 5 / 5**

> This checklist helps you confirm each milestone toward "understanding and being able to contribute independently".
> Complete it in order; don't skip.

---

## Part 1 · get set up, run your first test

- [ ] Finish reading [README.md](../README.md) — understand what the project is
- [ ] Follow [docs/getting-started.md](getting-started.md) to set up the environment (guest-state tests, no account / .env needed)
- [ ] Run `npm run test:smoke` successfully (use `BROWSER_CHANNEL=chrome` when bundled Chromium can't be downloaded)
- [ ] Run `npm run report` and see smart-report.html

---

## Part 2 · understand the architecture

- [ ] Read [docs/architecture.md](architecture.md) — understand each layer's responsibilities
- [ ] Use `HEADLESS=false npm run test:smoke` to watch the browser actually run
- [ ] Open `../testcases/watch.feature` (the feature main library is at the Playwright-Web-Agentic-Engineering-Automation repo root; automation only reads this layer), compare it with `tests/ui/watch.steps.ts`, and understand the Gherkin → step mapping
- [ ] Open `src/pages/search-results.page.ts` and look at the composite method (`applyFilter()`) and how the selector declaration area is written
- [ ] Open `src/fixtures/test.fixtures.ts` and understand the fixture injection mechanism

---

## Part 3 · write your first test

- [ ] Read [docs/writing-tests.md](writing-tests.md) — full flow explanation
- [ ] Pick an existing feature file and add a new `@regression @auto` Scenario to it (without `@auto` it won't be generated by bddgen and the test won't run)
- [ ] Run `npx bddgen` to see the step error hints
- [ ] Fill in the corresponding step definition
- [ ] Run in `HEADLESS=false` mode and confirm the test passes
- [ ] Read [docs/running-tests.md](running-tests.md) — understand all execution options

## Confirm the key knowledge points

A newcomer should be able to answer these questions:

**Architecture**

- What is the difference between BDD declarative and imperative?
- What is a composite method? When do you need to add one?
- Why do YouTube tests not need login setup / storageState?
- Why do selectors use `getByRole` / `getByText` instead of `data-testid`?
- How does fixture injection work?

**Operations**

- How do you run only the watch-page-related tests?
- How do you run when the machine can't download Chromium?
- What does `bddgen` do? When do you need to run it manually?
- Where do you look for screenshots when a test fails?

## When you hit a problem

Try these in order; if you can solve it earlier, don't go further:

1. **Check the Report**: `npm run report` — failure screenshots, console log, and network errors usually already explain the cause
2. **Re-run with a browser**: `HEADLESS=false LOG_LEVEL=debug npm test -- --grep "scenario name"` (note the `--`; without it npm swallows `--grep`)
3. **Playwright Inspector**: `npx playwright test --project=ui --debug` — step through execution and observe DOM state
4. **Codegen to find a selector**: `npx playwright codegen https://www.youtube.com` — operate the UI to auto-generate locators
5. **Claude Code analysis**: hand the error message or the failing test file to Claude Code

   ```
   # Launch under Playwright-Web-Agentic-Engineering-Automation/
   claude

   # Example prompts
   "This scenario failed with the error below, help me find the cause: [paste error]"
   "Help me add an assertCommentsVisible() method to WatchPage"
   "Does this step violate the declarative principle? [paste code]"
   ```

6. **Playwright MCP**: if a Playwright MCP server is configured, Claude Code can directly control the browser to screenshot and read the DOM, so you don't have to manually open a browser to inspect selectors; to add automation implementation for an existing `@auto` scenario, pair it with the `/auto-playwright-agentic-automation-workflow` skill, letting the planner agent automatically run live to produce an evidence map and the generator write the implementation from it
7. **Check common issues**: [Getting Started — Common issues](getting-started.md#common-issues)
8. **Ask a QA colleague**
